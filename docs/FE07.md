# FE07 — Tool results and structured output

Live application: https://leaddesk-capstone.vercel.app/discovery

Tool definition: `src/lib/tools.ts`; input and result schemas/rubric: `src/lib/qualification.ts`; lifecycle renderer: `src/components/tool-result.tsx`; completed component: `src/components/score-card.tsx`. The route imports the exported server tool, with Zod schemas for both boundaries and a deterministic execute function. The server validation, chat transport, useChat, and message renderer share an inferred LeadMessage type from the tool definition. The message renderer narrows the four supported state values with a runtime type guard rather than a state cast.

## Review improvements

The first two states previously shared almost the same card. Collection now shows explanatory preparation text and skeleton rows without premature input data. Execution shows a labeled business/project/budget/timing/authority summary and scoring feedback. Success is a score card with reasons and next action; failure uses an alert with retry guidance. Invalid returned data also shows a safe error instead of crashing. There is no JSON dump and no artificial production failure switch.

`/playground/tools` explicitly labels its states as sample fixtures. A valid deterministic scoring execution has no external network dependency and normally succeeds; invalid input is rejected at validation. Tests exercise thrown execution validation and the designed output-error UI separately, without claiming a simulated failure is a real provider failure.
