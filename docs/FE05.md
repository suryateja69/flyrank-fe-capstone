# FE-05 capstone skeleton

The existing LeadDesk application provides the capstone skeleton described in SPEC.md. This change fixes service health on protected preview deployments: the browser fetches relative `/api/health` using its existing same-origin session. It no longer makes an unauthenticated server request to the preview hostname. The displayed status and timestamp come from a validated API response, with loading, timeout, error, retry, and unmount cancellation states.

| Specification area | Implementation |
| --- | --- |
| Overview | `/` introduces the workspace and links to discovery |
| Primary flow | `/discovery` provides the guided project conversation |
| Preferences | `/settings` provides validated, device-local preferences |
| Project context | `/about` explains purpose, qualification and data handling |
| Service health | `/health` fetches `/api/health`; provider configuration is reported separately from provider availability |
| Component playground | `/playground` and `/playground/tools` provide component and typed tool examples; `/playground/3d` and `/playground/shader` are optional visual experiments |
| Shared shell and theme | `src/app/layout.tsx`, `src/components/navigation.tsx`, and `src/app/globals.css` provide navigation, skip link, responsive layout, and shared color/radius tokens |
| Environment | `.env.example` documents the server-only Google provider key and optional model; skeleton and health work without a provider key |
| Quality pipeline | `.github/workflows/ci.yml` runs install, typecheck, coverage, production build and Chromium E2E on pushes and pull requests |
